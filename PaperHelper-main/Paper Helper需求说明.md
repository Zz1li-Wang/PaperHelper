## 1. 项目概述

Paper Helper 是一个面向科研人员的 AI Research Workspace，用于支持研究方向探索、文献阅读、资料整理、研究讨论和论文写作等持续性的科研活动。

系统以 Workspace 为基本工作单位。一个 Workspace 对应一个相对独立的研究项目，用户可以在其中持续加入论文、报告、网页、研究方案、笔记等材料，并围绕这些材料与 Agent 展开讨论和研究。

Agent 长期参与 Workspace 中的工作，通过阅读已有材料、检索外部文献、整理研究信息、分析不同研究之间的关系，并协助用户形成阶段性的研究成果。

Paper Helper 希望解决的核心问题，是科研过程中大量信息和认知状态难以持续积累的问题。

## 2. 项目背景

当前的大语言模型已经能够较好地完成论文总结、翻译、问答、润色、文献检索等工作。

这些能力能够提高单个科研任务的效率，但科研本身具有明显的长期性和连续性。一项研究通常需要持续数月甚至更长时间，期间会不断产生新的论文、新的观点、新的问题和新的研究判断。

研究者阅读一篇论文之后，通常不会只留下一个摘要。这篇论文可能补充某个已有观点，也可能与之前的研究结论产生冲突，还可能带来新的研究方向。随着材料不断增加，研究者对整个问题的理解也会随之变化。

目前常见的大模型使用方式主要以单次对话或者单次任务为单位。用户每次开始新的任务时，通常需要重新提供研究背景和上下文。不同时间产生的论文总结、讨论结果、研究判断和写作内容也容易散落在不同的对话和文件中。

这种使用方式很难支持长期科研活动。

Paper Helper 希望把研究过程中产生的材料、理解和讨论持续沉淀到同一个 Workspace 中，使后续工作能够建立在已有研究基础之上。

因此，即使未来模型本身已经能够非常准确地总结和理解论文，科研过程中的信息连续性、研究状态维护以及长期上下文组织仍然具有独立价值。

## 3. 产品愿景

Paper Helper 希望成为科研人员长期使用的研究工作空间。

用户可以把一个研究方向从早期探索一直维护到研究方案形成、论文写作以及最终成果输出。

随着研究推进，Workspace 会逐渐积累相关论文、研究问题、研究观点、阶段性判断和已有成果。

Agent 通过这些信息理解用户当前正在研究的问题，并根据新的输入持续更新对研究项目的理解。

理想状态下，用户使用 Paper Helper 一段时间之后，不需要反复解释自己的研究背景。Agent 应当知道当前关注的问题、已经阅读过的材料、之前讨论过的方向以及目前仍然存在的研究空白。

用户负责研究方向和最终学术判断，Agent 负责信息获取、整理、分析、辅助推理和研究过程中的大量执行工作。

## 4. 产品定位

Paper Helper 的整体定位为：

> 面向持续科研活动的 AI Research Workspace。

论文阅读、文献检索、研究讨论和论文写作都属于这个 Workspace 中的具体工作场景。

Paper Helper 不计划通过自建大规模论文库覆盖所有学科。系统主要依赖用户提供的材料以及可访问的外部论文来源获取研究信息。

产品价值主要来自 Workspace 中长期积累的研究上下文，以及 Agent 对这些上下文的持续使用。

## 5. 目标用户

Paper Helper 面向已经处于某个研究领域，并具有实际科研需求的用户。

典型用户包括硕士研究生、博士研究生、高校科研人员、医生、工程研究人员以及其他需要长期阅读和整理学术资料的人群。

用户通常已经具备一定的研究背景。

有些用户可能只有一个较宽泛的方向，例如：

“我正在研究术中低血压。”

有些用户已经形成较明确的问题，例如：

“我想研究老年非心脏手术患者术中低血压与术后谵妄之间的关系。”

还有一些用户可能直接以已有资料作为起点，将近期阅读的论文、开题报告或者研究方案加入系统。

Paper Helper 应当能够从这些不同程度的初始信息开始工作，不要求用户在建立项目时完整填写研究方案。

## 6. Workspace

Workspace 是 Paper Helper 的基本项目单位。

一个 Workspace 对应一项相对独立的研究工作。

例如：

“术中低血压与术后认知功能研究”

可以作为一个 Workspace。

随着研究推进，这个 Workspace 中可能逐渐包含论文、网页资料、研究报告、笔记、研究方案、实验设计、论文草稿和演示材料等内容。

一个 Workspace 可以持续较长时间，并可能产生多种研究成果。

因此 Workspace 与最终论文之间并不存在严格的一一对应关系。一项研究可能产生多篇论文，也可能最终形成综述、研究报告或者其他成果。

Workspace 的作用是维持整个研究过程的连续上下文。

## 7. 多 Workspace 与知识复用

一个用户可以同时维护多个 Workspace。

不同研究项目之间默认保持独立，以避免不同领域的上下文互相干扰。

与此同时，一些基础信息具有复用价值。

例如，同一篇论文可能同时被两个研究项目使用。论文的标题、作者、正文、研究方法和实验结果等基础信息可以直接复用，不需要重复解析。

这篇论文在不同 Workspace 中的重要程度、与当前研究问题的关系以及用户对它的评价，则需要分别保存。

因此，系统需要区分材料本身的信息与材料在具体研究项目中的语境信息。

这一原则将在后续的数据模型和知识管理设计中进一步细化。

## 8. Workspace 创建与初始输入

用户创建 Workspace 时，只需要提供当前已有的研究信息。

用户可以直接描述正在研究的问题，例如：

“我最近在研究术中低血压对术后认知功能的影响。”

也可以上传已有论文、报告、研究方案、Word 文档或其他文件。

用户还可以提供论文链接和网页链接。

这些内容共同构成 Workspace 的初始上下文。

系统在获得这些信息后，对当前研究主题和已有材料进行初步整理，并开始建立 Workspace 中的研究内容。

创建过程应尽量轻量，不要求用户提前掌握复杂的产品结构。

## 9. Agent 的角色

Agent 是 Workspace 中的研究协作者。

用户可以直接向 Agent 发出任务，也可以与其围绕当前研究方向进行讨论。

对于目标明确的小型任务，例如论文总结、内容提取、翻译或生成 PPT，Agent 可以直接执行。

对于开放程度较高的任务，例如：

“帮我调研一下这个方向目前的发展情况。”

Agent 可以进行更完整的研究过程，包括搜索相关论文、筛选材料、阅读重点内容、比较不同研究以及整理阶段性结论。

任务的执行深度由用户意图和任务复杂度决定。

这样可以同时支持快速工具型使用和较长时间的研究工作。

## 10. 核心使用过程

Paper Helper 不预设严格的科研流程。

用户可以根据自己的研究习惯自由使用 Workspace。

一种典型过程可能是：

用户首先创建一个 Workspace，并输入当前研究方向。

之后与 Agent 讨论研究问题，并逐渐明确需要关注的内容。

用户可能要求 Agent 检索某个方向的相关文献。

Agent 将相关论文加入研究材料，并完成初步整理。

用户也可以把自己正在阅读的论文继续加入 Workspace。

随着材料增加，Agent 对当前研究问题的理解逐渐完善。

之后用户可能继续讨论某个研究方法，比较不同论文的实验设计，查找研究争议，或者开始整理综述。

当进入论文写作阶段时，Agent 可以利用 Workspace 中已有材料协助完成论文结构、文献综述和部分文本写作。

研究过程中如果再次加入新的论文，系统应能够继续利用这些信息参与后续工作。

整个过程中，用户可以随时改变研究方向或者回到之前的问题。

Workspace 负责保存这些活动之间的联系。

## 11. 研究材料

论文、网页、报告、研究方案、笔记等内容都属于 Workspace 中的研究材料。

研究材料进入 Workspace 后，应当能够在之后的研究过程中持续使用。

用户无需为了后续讨论重复上传同一份材料。

系统需要保存材料来源，并支持后续检索和引用。

同时需要区分几类不同的信息来源。

论文原文属于原始材料。

Agent 对论文内容形成的总结和分析属于系统解释。

用户自己形成的观点和判断属于用户研究内容。

这些信息在可信度和用途上存在差异，系统后续需要保留这种来源关系。

## 12. 研究上下文

随着 Workspace 持续使用，系统需要逐渐形成对当前研究的整体理解。

这种研究上下文至少应包括当前研究主题、主要研究问题、已有重要材料、正在关注的研究方向、关键观点、文献之间的关系、存在争议的问题以及仍然缺少信息的部分。

这些内容应主要由系统根据用户行为和研究材料自动维护。

用户可以查看和修正其中的重要内容，但不应承担大量手工整理工作。

Research Context 可以理解为 Workspace 当前研究状态的一种概括。

具体应该以什么界面和数据结构呈现，需要在后续产品设计阶段继续讨论。

## 13. Agent 的主动性

Paper Helper 中的 Agent 应具备一定主动研究能力。

当用户要求调研一个研究方向时，Agent 可以主动检索更多资料。

如果新的论文与之前的研究结论存在明显冲突，可以提醒用户。

如果一段论文写作中的重要观点缺少文献支持，也可以指出证据不足。

当新的材料明显改变已有研究判断时，系统可以提示用户相关变化。

这种主动行为需要围绕用户当前研究目标展开，并保持可控。

重要的研究结论、研究方向和学术判断仍由用户决定。

Agent 主要承担信息搜索、材料处理、信息组织、问题发现、方案建议和研究辅助等工作。

## 14. 信息来源与可追溯性

科研场景对信息可靠性要求较高。

Paper Helper 在设计上需要尽量保留重要结论与原始来源之间的关系。

当 Agent 给出某项研究判断时，用户应当能够查看相关论文或者材料。

如果某个观点属于 Agent 根据已有信息形成的推断，系统需要将其与文献中的明确结论区分开。

如果不同论文之间存在明显争议，也应尽量保留这些差异。

可追溯性将作为 Paper Helper 后续设计中的基础要求。

## 15. 写作与成果生成

Paper Helper 支持论文相关的写作工作，包括文献综述、论文结构、研究报告、论文段落、开题材料和 PPT 等。

这些内容建立在 Workspace 已有研究材料和上下文基础之上。

当用户要求撰写综述时，Agent 可以优先使用 Workspace 中已经整理的论文和研究信息。

如果现有材料不足，可以继续检索相关文献。

生成的内容需要尽量保留与研究来源之间的关联，方便用户进一步核查和修改。

生成结果作为 Workspace 中的研究成果保存，后续可以继续编辑和使用。

## 16. Chat

自然语言对话是用户与 Agent 交互的重要方式。

用户可以通过 Chat 提出问题、发出任务、讨论研究方向或者修改 Agent 的判断。

不过长期研究信息不能仅依赖聊天记录保存。

论文、研究材料、研究上下文和生成成果需要作为 Workspace 中独立的信息存在。

Chat 主要承担交互作用。

Workspace 负责保存长期研究状态。

## 17. 核心产品对象

当前阶段暂时确定几个主要产品对象。

Workspace 表示一项持续进行的研究项目。

Source 表示进入项目的原始研究材料，例如论文、网页和文档。

Research Context 表示系统当前对该研究项目形成的整体理解。

Conversation 表示用户与 Agent 的讨论过程。

Task 表示一次具体工作，例如搜索论文、分析材料或者生成文档。

Artifact 表示研究过程中产生的结果，例如综述、论文草稿或者 PPT。

这一阶段只确定产品概念，暂不直接映射为数据库表或者具体技术模块。

## 18. MVP 范围

第一阶段需要优先验证 Workspace 模式是否能够提升长期科研过程中的连续性。

MVP 需要形成一个完整的基本使用闭环。

用户可以创建 Workspace 并描述研究方向。

用户可以上传论文或提供论文链接。

系统能够解析和保存这些材料。

用户可以围绕 Workspace 与 Agent 持续讨论。

Agent 能够使用 Workspace 中已有材料回答问题和执行研究任务。

Agent 可以根据研究方向检索外部论文，并将需要的论文加入 Workspace。

用户可以要求 Agent 调研某个研究方向。

Agent 可以利用已有研究材料生成综述、报告或 PPT 等阶段性成果。

用户离开后再次进入 Workspace，之前积累的研究背景和材料仍然可以继续使用。

第一阶段的重点是验证这个研究闭环，而不是提前建设复杂的科研自动化系统。

## 19. 暂不纳入第一阶段的能力

MVP 阶段暂不建设覆盖各学科的大规模自有论文库。

复杂的知识图谱可视化暂时不作为核心功能。

Multi-Agent 架构暂不作为产品要求，后续是否采用由技术设计决定。

完全自主、长时间无人干预的科研 Agent 暂不作为第一阶段目标。

多人协作、实验自动执行、期刊投稿管理和审稿流程也暂时不进入 MVP。

这些能力需要在核心 Workspace 模型得到验证之后，再根据实际使用需求决定是否加入。

## 20. 产品设计原则

Paper Helper 后续的功能设计需要围绕长期科研过程展开。

新的功能需要能够进入 Workspace 的研究上下文，并在之后继续发挥作用。

重要研究信息应当尽量保留来源。

Agent 产生的分析、推断和原始文献事实需要保持区分。

系统应减少用户反复提供研究背景的需要。

随着新的研究材料进入，系统需要能够继续更新对当前研究的理解。

Workspace 中的信息结构应尽量由系统自动维护，避免把整理负担重新交给用户。

## 21. 核心验证目标

Paper Helper 第一阶段最重要的验证目标，是确认长期 Workspace 是否能够产生明显优于普通 AI 对话的科研体验。

如果用户持续使用一个 Workspace 数周之后，系统仍然能够理解用户当前研究的问题、已经阅读过的论文、之前形成的观点以及尚未解决的问题，说明 Workspace 机制具有实际价值。

理想情况下，当用户加入一篇新的论文时，Agent 能够结合现有研究背景理解它与当前项目之间的关系。

当用户再次讨论之前的问题时，Agent 能够使用过去积累的材料继续工作。

当用户进入论文写作阶段时，前期研究过程中积累的信息可以直接用于写作。

这些能力将作为产品早期最重要的验证方向。
